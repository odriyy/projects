EMBO: Embolization Particle Sizing System

Completed 2026 PCB Design ESP32-S3 Computer Vision Ultrasonics Medical Device

A closed-loop medical device that automates and quality-controls the preparation of gelatin foam embolic agents for interventional radiology, using real-time computer vision and ultrasound sensing to measure and control particle size.

From Slurry to Certainty

Embolization procedures use tiny gelatin foam particles to deliberately block blood vessels, treating tumours, fibroids, and bleeding. Before every procedure, a clinician manually prepares the particle slurry by pumping two syringes back and forth until it reaches a "pudding consistency" — a method unchanged since the 1970s, with no measurement and no standard. Particle size directly affects clinical outcomes, and two clinicians performing the same prep can produce very different distributions. EMBO replaces this manual process with a sensor-guided system that measures and controls particle size in real time.

Final prototype at the SUTD engineering exhibition.

The Concept: Closed-Loop Preparation

01

Automated Mixing

Two stepper motors drive syringe plungers back and forth with precise speed, stroke, and cycle control, replacing manual pumping.

02

Real-Time Sizing

A Raspberry Pi 5 running YOLOv8 tracks particle size and IQR via microscope camera, while a 1MHz ultrasound signal chain measures slurry attenuation as a second, independent estimate.

03

Automatic Stop

A PID control loop on the ESP32-S3 adjusts stroke count based on live sensor feedback and halts mixing automatically once the clinician's target particle size is reached.

Core processing unit layout, highlighting data lines reserved for external communication.

  • ESP32-S3-WROOM-1-N4 Main Controller: Runs the PID control loop, drives both stepper motors, manages the ultrasound signal chain, and interfaces with the TFT touchscreen UI and Raspberry Pi.
  • 2x TMC2209 Stepper Drivers: Field-replaceable plug-in modules that drive the two syringe plungers via UART, with StallGuard providing an indirect force-feedback signal.
  • Ultrasound Signal Chain: An AD9833 DDS generates a 1MHz sine wave, amplified by an OPA2354 Tx stage (G=4.9) and driven through a transducer; the received signal passes through a two-stage OPA2354 Rx amplifier (100x gain) and a BAT54 envelope detector before reaching the ADC.
  • Turbidity Sensing: An APDS9960 measures ALS transmission and a MAX30102 measures backscatter, giving a second, optical estimate of slurry turbidity independent of the acoustic path.
  • Force Sensing: Two load cells with HX711 24-bit amplifiers sit at each syringe plunger contact point, acting as a hardware fallback if the TMC2209's UART-based StallGuard reading proves unreliable.
  • GPIO Protection Resistors: 220Ω resistors were added on every ESP32-to-TMC2209 control line in v3.4 after a hot-swap/spark incident damaged an earlier fabricated board.

Sensing System

Display breakout board: ILI9341 TFT + XPT2046 touch, connected via 20-pin IDC ribbon.
  • Computer Vision: A USB 2.0 microscope camera clamped to the syringe feeds frames to a YOLOv8 model trained on gelatin foam particles, running on a Raspberry Pi 5. It reports median particle diameter and IQR back to the ESP32-S3 over UART at 921600 baud.
  • Diffused Backlight: An LED panel backlights the syringe to maximize particle contrast for the vision pipeline.
  • Particle Size Model: Mixing follows first-order breakage kinetics, D(N) = D_min + (D₀ − D_min) × e-kN, where N is stroke count and k is an empirically measured shear constant. The PID loop uses live D(N) measurements to schedule remaining strokes.

Engineering Challenges

No Existing Measurement Standard

The Problem

Gelfoam preparation has been done by manual syringe pumping since the 1970s, with no device measuring particle size during the process, and no baseline data to calibrate against.

The Solution

We built two independent sensing modalities — computer vision and ultrasound attenuation — and empirically fit a first-order breakage kinetics model to relate stroke count to particle size, giving the PID loop a measurable target to control against.

GPIO Damage from Hot-Swapping

The Problem

Hot-swapping a TMC2209 module on the fabricated v2.51 board caused a spark that damaged the ESP32-S3's GPIO lines, halting bring-up.

The Solution

In v3.4 we added 220Ω protection resistors on every ESP32-to-TMC2209 control line, an 8A on-board backstop fuse, and reverse polarity protection to harden the board against future incidents.

Shared SPI Bus Conflicts

The Problem

The AD9833 signal generator, ILI9341 display, and XPT2046 touch controller all share the SPI2 bus, but each requires a different SPI mode and clock speed.

The Solution

Each peripheral's library switches SPI mode per transaction via SPI.beginTransaction(), letting all three devices safely share the bus without cross-talk.

HX711 Timing Sensitivity

The Problem

The two HX711 load cell amplifiers share a single clock line, but standard HX711 libraries assume one dedicated clock per chip, and the chip powers itself down if its clock pin sits high for more than ~60µs.

The Solution

We wrote a custom shared-clock, per-channel bit-bang driver pinned to a dedicated core with short critical sections, keeping both channels readable without either chip powering down mid-read.
